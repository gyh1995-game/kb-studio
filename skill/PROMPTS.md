# KB Studio · 内容输出规范（Skill）

> 这一份是「一条链接进来之后，产出该长什么样」的**唯一规范**。
> 网页服务读它（`/api/config` 的 `skill` 字段报告它在不在），你也可以直接把本文件交给
> 任意 agent（Claude Code / Codex / OpenCode / 自己写的脚本），用同一套流程得到同一份产出。
> 目的：这套库开源出去后，别人接自己的模型也不会得到两种格式的卡片。
>
> 常数、正则、字段名以 `server.py` 为准（下面标了行号附近的函数名）。**这份文档不复述代码，
> 只定口径**；两者不一致时以代码为准，并回来改这份文档。

## 0. 硬规则（先读这条）

1. **抓不到就说抓不到**，并给出下一步动作（补 cookie / 粘正文 / 换通道）。
   **禁止编造原文、数据、作者、点赞数。**
2. 每条链接**只落一份原料**：`source`（原文链接）、`platform`、`author` 必须保留 ——
   署名是合规要求，也是回头判断可信度的依据。
3. `raw/` 的「原文」一节是作者的话，AI 不许改写；「消化稿」一节和 `wiki/` 由 AI 维护，可以重生成。
   本人手动改过原文后点「按原文重新生成」，旧消化稿进 `inbox/trash/`，不覆盖。
4. cookie 只落本机 `cookies/`，不写进笔记、不外传，接口只回元信息。
5. **处理过程不进正文。** 「这条什么时候重跑的、备份在哪个 trash 文件、用了哪个转写引擎、
   有没有调模型」属于 `log.md`。原料里只允许留「这段文字可能有错、不是作者原话」这种
   **读者用得上的**说明。
6. **同一份信息只有一个出口。** 原料长成了哪些卡，只由卡文件 frontmatter 的 `from_raw` 决定
   （`grownCards()` 现算），正文里**不写**卡列表小节；卡指向原料，只在正文末尾写**一行**
   `出处：[[原料标题]]`，这一行由 `write_card()` 补，模型自己写的「出处：」「来源：」会被
   `strip_meta_echo()` 剥掉。
7. **模型不许输出 frontmatter、不许输出 `---`、不许自己估时长和类型。**
   元数据全部由代码写（见 §4）。

## 1. 输入 → 通道选择

| 输入 | 动作 |
|---|---|
| 链接（网页 / 博客 / 公众号） | 直连抓取 → 正文清洗 → 图片入 `raw/assets/` |
| 链接（知乎 / 抖音 / 小红书 / ins / fb） | 需要登录态：先探一次（`/api/fetch`），读不到就按 hint 要 cookie 或要正文 |
| 链接（B站） | 字幕优先（含 AI 字幕）；无字幕抽音频 → 本地转写（FunASR paraformer-zh 优先，退回 faster-whisper），保留可点击时间戳 |
| 本地文件 | md/txt/html 直读；pdf 走 pymupdf；docx 走 zipfile；图片存 assets；音视频转写 |
| 直接粘贴的正文 | 跳过抓取，直接进第 2 步 |

**图文还是视频由工具自己判**（`media_type_of()`）：`note_kind=image` 走图片识字，
`note_kind=video` 走「下载 → 转写 + 抽帧识字」。判错的表现是「视频只识了封面图」或
「图文被硬塞进转写」，两种都要回来修 `fetchers.py`，不要手改原料绕过。

抓取阶段还会做两件**数据层**的修复，别指望 CSS 兜：
- `unbreak_urls()`：知乎 / 公众号的正文里链接常被硬断成三行（`https://` / 域名 / 路径），
  在入库前拼回一条。断链喂给模型会被读成三个词，前端也只能渲染出三段断文字。
- `reflow_text()`：整个回答被压成一行的，恢复成段落。

## 2. 排版契约（这一段是「输出不混乱」的硬判据）

小模型最容易坏在这里。以下每一条都能机器判定，违反即判格式不合格。

### 2.1 链接

- 正文里的链接一律 `[短锚文本](URL)`。**禁止裸 URL 夹在句子中间。**
- 确实要贴原始 URL（引用出处、给下载链）→ 让它**独占一行**，前后各留一个空行。
- **表格单元格里不许放 URL**：一个长 URL 会把整列撑爆，而且很多解析器会跳过
  「行首行尾都有 `|`」的链接行。要放就只放 `[原文](URL)`。
- 锚文本里不许再套方括号。
- 内部双链一律 `[[卡片文件名]]`，不写相对路径、不写 `.md` 后缀。
  （Obsidian 的 `newLinkFormat` 设成「最短可能的链接」时，带 `/` 的路径会被解析成另一个键。）

### 2.2 块级元素

- **标题只用 `#` 和 `##` 两级**，`#` 只给文件名那一行（由系统写），正文里从 `##` 起。
- 标题行里不许出现裸 URL。
- **列表项一条一行，不许在条目中间手动换行**（模型爱按 80 列折行，折完一条变两条）。
  一条确实长 → 写成两句，或拆成子项。
- 段落之间恰好一个空行；不许出现三个以上连续空行、不许行尾带空格。
- 表格只在不写清楚会丢结构时用；用时**每行列数必须完全一致**，且遵守 2.1 的单元格规则。
- 代码 / 命令 / 配置片段用围栏（``` ），围栏里的内容不会被拿去生成标签（`strip_code()`）。

### 2.3 转义与排版

- 正文里出现的 `*` `_` `|` 如果不是 Markdown 语法，必须写成 `\*` `\_` `\|`。
- 强调只用 `**粗**` 和 `*斜*`；`==高亮==` 是他自己在阅读页打的，模型不许生成。
- 中文与英文 / 数字之间加一个半角空格（`DeepSeek 的 265 字/分`）；全角标点外侧不加空格。
- 不用 emoji。状态、层级、类型都靠文字和 frontmatter 表达。

### 2.4 不许出现在卡片正文里的东西

| 不许 | 为什么 | 该在哪 |
|---|---|---|
| frontmatter / `---` | 元数据只有一个写入方 | `write_card()` |
| `# 一级标题` | 文件名就是标题，重复一遍会渲染出两个 | 系统写 |
| 「出处：」「来源：」 | 格式每轮不一样，还常和 platform 拼重复 | 系统补一行 `出处：[[…]]` |
| 「类型：视频」「约 X 分钟」 | 由抓取结果算，模型估的不准 | frontmatter `media_type` / `est_min` |
| 「这张原料长成的卡」小节 | 与右栏同一件事 | `from_raw` |
| 处理日志（重跑时间 / 备份路径 / 引擎名） | 读者用不上 | `log.md` |

### 2.5 措辞纪律（治「字段被写脏」）

这四条抄自 Graphiti（Zep 的知识图谱抽取）的抽取提示词，对小模型跑偏的抑制最直接：

- **字段里不写元话语**：不许出现「（隐含…）」「我认为」「不过…」「可能需要」这类推理或犹豫。
- **一个位置只放一个值**：不许写成「A，或者 B，或者 C」。
- **只有三种合法取值**：原文里能指认并归一化的值 / 保留已有的旧值 / 写「无」。
  不许留空、不许猜、不许用「大家都这样」当依据。
- **转述但不许泛化**：原文里的具体名词、数字、型号、量级、地名必须活下来；
  句子结构可以重写，但不许把「他测了 3 个账号」写成「多数人」。主语用实体名，不用「它 / 这 / 他们」。
- **一次出现不是一条规律**：只发生过一件事的，写进「我的疑问」当待验证，不要写成普适主张。

## 3. 三层卡的骨架

### 3.1 卡名 = 一句主张（不是主题）

概念卡的标题写成**主谓句**，读一遍就能同意或反对：

| 好 | 坏 | 坏的毛病 |
|---|---|---|
| 量产变体不等于流量 | 关于流量的一些思考 | 主题不是主张 |
| 知识库的价值在编译层不在存储层 | 知识库 | 光杆名词，无法同意/反对 |
| 强制产出疑问比摘要更能防止假读 | 学习方法 | 悬在空中的抽象词 |
| AI 该持续维护结构，人只负责扔原料和提问 | AI 该持续维护结构 | 截断的从句，离开上下文读不出主张 |

- 长度 **8–25 个汉字**（英文 3–12 词）。
- 不带 `？`（那是问题卡）、不带引号、不带书名号、不带日期、不带平台名。
- 这一条来自 Zettelkasten 的 claim-style title 传统：Matuschak「Notes note themselves」——
  只有主张能被复用、能被反驳、能在图谱里接上别的卡。

### 3.2 每层用**不同的骨架**（同构模板是错的）

**概念卡**（`wiki/concepts/`）—— 一条能独立成立的主张：

```
主张：<一句话，和卡名同义但可以更完整>
为什么成立：<本文里能指认的依据：数字 / 例子 / 原句 / 步骤>
边界：<什么条件下不成立>
用在哪：<会改变你哪一个动作>
```

**连接卡**（`wiki/connections/`）—— 两个已有概念之间的关系，**必须接得上**：

```
[[概念甲]] ↔ [[概念乙]]
关系：<前置 / 矛盾 / 同结论不同路径 / 上下位>
为什么真的相关：<不是「都在讲 AI」这种表面相似，要能说出机制>
在什么情况下这条连接会断：<两边各自失效的条件>
```

**问题卡**（`wiki/questions/`）—— 读完仍然没想清楚的：

```
问题：<能在 20 字内问完的短问题，它直接当卡名>
为什么值得问：<卡在哪>
我目前的答案或猜测：<没有就写「还没有」，不许编>
下一步要什么材料才能回答：<要查什么 / 要丢什么链接进来>
```

问题卡必须**合上原文也能作答**（SuperMemo 的 minimum information principle、
Anki 的「一张卡只问一件事」）。判据：把卡名单独贴出来，一个没读过原文的人答得了吗？
答不了 → 要么改窄问题，要么别建卡。

### 3.3 维度标签用行首粗体，不用 `##`

`为什么成立：` `边界：` `用在哪：` 这类维度**写在行首**（可以加粗），不要升格成 `## 标题`。
升格之后每张卡有四个小节，Obsidian 的右击大纲和图谱都会被撑乱，而且模型会开始往里塞第五个维度。

### 3.4 什么才算一条有效记录（AI 和用户用同一把尺）

| 判据 | 过关 | 不过关 |
|---|---|---|
| 离开这条内容还成立 | 换个平台、换个人、把原文删掉，这句话照样对 | 「这条视频讲了 hypit」——删了原文就没了 |
| 能被同意或被反对 | 「量产变体不等于流量」 | 「100 个变体」「五组件骨架」（名词，不是主张） |
| 讲得出依据 | 依据能在原文里指认 | 只有断言，或依据是「大家都这样」 |
| 讲得出边界 | 说得出它在什么场景失效 | 放到哪都对 —— 那是废话，不是知识 |
| 用得上 | 说得出会改变你哪一个动作 | 说不出（这栏空着就别建卡） |
| 正文够厚 | 主张+依据+边界+用在哪，去空白 ≥ 90 字 | 一两句话的口号 |
| 原子性 | 一张卡只装一个主张 | 一张卡里写了三条不相干的观点 |

**一律不许当概念**（记录的是「这一条」，不是知识，留在原文里就够）：
产品名 / 项目名 / 仓库名 / 人名 / 账号名；许可证、版本号、运行环境、安装命令；
点赞、收藏、评论、转发、播放量、star 数、藏赞比这类互动数据；作者 IP 归属、发布时间；
被当成卖点写出来的数字口号（「1 亿播放量」那种）。

**先查库里已有的卡**：这篇如果是在印证一张已有的页，不要另起近义名，写成
`- 并入：<已有卡名> —— 主张｜为什么成立｜边界｜用在哪`，系统会把这篇追加到那张卡上。
一个主张只留一张卡。一条新素材应该**回填 10–15 张已有页**，而不是每条素材都发一批新卡。

### 3.5 数量闸门

一次消化最多 **3 概念 / 2 连接 / 3 问题**（`compile_cards()` 硬拦）。
连接的另一头对不上库里已有的卡 → 直接进 `dropped`，不建孤儿卡。

## 4. 元数据契约（谁写、写什么、怎么验）

frontmatter 的标量**只有一个写入方**：`write_card()`（新建）或 `_fm_set()`（改状态 / 类型 / 预估）。
所有自由文本标量走 `q()` 加双引号 —— 标题里出现 `: ` 或 `#` 会把 YAML 撕开，
而卡片标题就是自由文本。

| 字段 | 谁写 | 取值 | 机器判据 |
|---|---|---|---|
| `title` | `write_card` | 一句主张，8–25 字 | 不带 `？`、不带平台名、不是光杆名词 |
| `type` | `write_card` | `concept` / `connection` / `question` / `raw` / `system` | 白名单 |
| `source` | 抓取结果 | 原文 URL 或「本地文件」 | 有 `[[` 或换行即判脏 |
| `platform` | 抓取结果 | 知乎 / 抖音 / 小红书 / B站 / 公众号 / 网页 / … | 白名单 |
| `author` | 抓取结果 | 作者署名 | 非空 |
| `captured_at` | `write_card` | `YYYY-MM-DD` | 日期格式 |
| `from` | `write_card` | 原料标题 | — |
| `from_raw` | `write_card` | 原料**路径**（不是双链） | 文件存在 |
| `media_type` | `media_type_of()` | 文本 / 图文 / 视频 / 音频 / 其他 | 白名单，**模型不许自填** |
| `est_min` | `est_minutes()` | 正整数 | 同上 |
| `duration_ms` | 抓取结果 | 视频/音频才有 | — |
| `dim` | 问题卡专用 | 边界 / 证据 / 与我 / 待验证 | 白名单 |
| `sources` | `write_card` / `_add_source_to_frontmatter` | 块状列表 `"标题\|URL"` | 跨来源累积，不覆盖 |
| `status` | `set_status()` | 未读 / 已读 / 待吃透 / 待实践 / 已内化 | 五个值，其余进 `STATUS_ALIAS` 折叠 |
| `tags` | `clean_tags()` | 流式列表 `["a", "b"]` | 见 §5 |

**`aliases` 的坑**：`[[卡名]]` 认的是**文件名**和 `aliases:`，`title:` 属性不算链接目标。
所以卡名必须同时是文件名（`card_name()` 负责），否则反链永远数不到。

## 5. 标签与状态治理

- 标签**不许含 `#`、空白、逗号、冒号、引号、方括号**（`TAG_BAD_CHARS`）。
  中英混排里的空白折掉而不是丢掉：`AI 工具` → `AI工具`（`norm_tag()`），
  因为 Obsidian 的 tag 本身就不允许空白。
- 长度 ≤ 12 字（`TAG_MAX_LEN`）。
- 一律拦下：维度词（边界 / 证据 / 与我 / 待验证 / 反例 / 前提）、状态词（五个状态及其别名）、
  处理日志词（消化生成 / 手写 / 并入 / 追问）、平台名（它们活在 `platform` 字段里）、
  色值（`#c4734a`）、CSS 选择器（`readBody`）、camelCase 标识符、纯数字纯符号。
- 代码块和行内 code 里的 `#xxx` 不是标签（`strip_code()` 先剥）。
- 一张卡最多 6 个标签（`tags_from_digest(..., limit=6)`）。
- **状态不是标签。** 一个事实只有一个容器：状态进 `status`，主题进 `tags`。
- 状态五个值，近义的合并进 `STATUS_ALIAS`（「已消化」→「已读」），
  不新增第六个值。写回时不在五值内的整句直接拒绝并报错。

## 6. 时长口径

常数分两类：**有出处的标出处，没出处的直说是产品自定**。不要拿流传数字当依据 ——
「Medium 用 265 wpm」这类说法查不到一手实现或官方文，属 folklore，不用。

| 常数 | 值 | 出处 |
|---|---|---|
| 中文默读 | **200 字/分** | `ngryman/reading-time` 源码：`wordsPerMinute = 200`，且注释写死 **"A CJK character is always a word"** —— 1 汉字按 1 词计。这是被部署最广的一份实现 |
| 英文网页阅读 | **200 词/分** | 同一实现的默认值 |
| 卡片（要能复述） | **150 字/分 · 150 词/分** | **产品自定**，没有一手来源；只表示「比初读慢一档」 |
| 图片 | **首图 12 秒，逐张 −1 秒，下限 3 秒** | `@tryghost/helpers` 的 `reading-minutes.js` |
| 视频 / 音频 | **= 平台时长** | 逐字稿就是那段视频，字数再算一遍等于计两次 |

- **中英混排分开折算**（`read_units()`）：一个英文单词平均 5 个字符，按字符数折中文会明显偏快。
- 图文按 0.8 系数放慢（图要看）。
- 代码块计入时长（`remark-reading-time` 同时 visit `text` 和 `code`）。
- 界面上只写「约 N 分钟」，**不进笔记正文**。
- 复习条目：想起这道题 40 秒 + 把原文里它那一段重读一遍（按原料长度平摊到各条疑问）。

## 7. 复习条目

一条疑问 = 一条复习条目（`append_review_tasks()`），每条带：

| 字段 | 含义 |
|---|---|
| `card` | 那张问题卡的路径（找不到就退回原料） |
| `raw` | 它出自哪份原料 |
| `media_type` / `est_min` | 类型和这一条要几分钟 —— 在入队那一刻就算好，前端只读不猜 |
| `platform` / `origin` / `url` | 来源三件套 |
| `due` | 到期日 |

仪表盘「今天该复习」的每一行显示 类型 · 预估 · 来源；阅读页「本篇待复习」只显示预估
（类型和来源就是上面那排芯片，同一页不写两遍）。勾完立刻从这一栏消失并计入「近期已完成」。

**消化稿必须写满 3 条「我的疑问」**，覆盖 边界 / 证据 / 与我 / 待验证 中至少两类。
没写 → 复习队列里不会有条目，前端会在结果区明确警告，并给出补救动作（按原文重新生成）。

## 8. 消化稿的结构（模型直接产出的那一节）

固定 8 段，顺序不变，段名一字不差：

```
## 核心观点        3-5 条，每条一句话，是这篇真正的主张。不复述背景，不写「本文介绍了」。
## 可执行清单      能照做的步骤 / 清单 / 参数；纯观点类写支撑论据。没有就写「无」。

## 10. 执行提示词在哪

真正发给模型的文本只有一份，在 `server.py`：

- `DIGEST_SYSTEM` —— 角色与硬规则
- `DIGEST_PROMPT` —— 本条素材的填充模板（`{title}` / `{platform}` / `{url}` / `{author}` / `{content}`）
- `GEN_CARD_SYSTEM` / `GEN_CARD_PROMPT` —— 「一句话生成卡」那条路径

**本文件不复述提示词原文**（复述就是第二个出口，两份迟早打架）。
要看当前生效的提示词：`python -c "import server; print(server.DIGEST_SYSTEM); print(server.DIGEST_PROMPT)"`。
改提示词只改 `server.py`，改完回来核对这份文档的口径有没有跟着变。

## 11. 批注归位（本人写，AI 归位）

他在阅读页选中一段 → 高亮写成 Obsidian 原生 `==…==`，批注写成 `> [!note] 批注 · 日期 · \`kb-xxxx\``
callout，紧挨在那一段后面（行号寻址，见 `app.js` 的 `data-ln` / `data-le`）。
界面上批注显示在**正文右侧那一栏**，不显示在正文里（`.md .cal.anno{display:none}`）。

AI 的处理动作：

1. 读批注 → 判断它是**理解**、**质疑**、还是**新线索**；
2. 理解 → 补进对应概念卡的正文；质疑 → 变成 `wiki/questions/` 的一张卡；
3. 新线索 → 登记为「下一步」并提示要丢什么链接进来；
4. 批注原文保留在卡片文件里 —— 那是他自己的话，不许改写、不许删。
