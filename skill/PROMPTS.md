# KB Studio · 处理规范（Skill）

> 这份文件是「一条链接进来之后，AI 该怎么处理」的**唯一规范**。
> 网页服务读它（`/api/config` 里的 `skill` 字段会报告是否存在），你也可以直接把本文件交给
> 任意 agent（Claude Code / Codex / OpenCode / 或你自己写的脚本）使用同一套流程。
> 目的：这套知识库开源出去后，别人接自己的模型也能得到同样的产出质量。

## 0. 硬规则（先读这条）

1. **抓不到就说抓不到**，并给出下一步动作（补 cookie / 粘正文 / 换通道）。**禁止编造原文、数据、作者、点赞数。**
2. 每张原料必须保留 `source`（原文链接）、`platform`、`author` —— 署名是合规要求，也是你回头判断可信度的依据。
3. `raw/` 的「原文」一节是作者的话，AI 不许改写；「消化稿」一节和 `wiki/` 由 AI 维护，可以重生成。
   本人手动改过原文后点「重新生成」，旧消化稿进 `inbox/trash/`，不覆盖。
4. cookie 只落本机 `cookies/`，不写进笔记、不外传、接口只回元信息。
5. **处理过程不进正文。** 「这条什么时候重跑的、备份在哪个 trash 文件、用了哪个转写引擎、
   有没有调 DeepSeek」属于 `log.md` / `agent.md`，写进原料就是污染。
   原料里只允许留「这段文字可能有错、不是作者原话」这种**读者用得上的**说明。
6. 一张原料文末只有**一份**卡列表（`## 这张原料长成的卡`），由 `render_card_section()` 写；
   模型自己 echo 出来的同名小节会被 `strip_card_sections()` 剥掉。

## 1. 输入 → 通道选择

| 输入 | 动作 |
|---|---|
| 链接（网页/博客/公众号） | 直连抓取 → 正文清洗 → 图片入 `raw/assets/` |
| 链接（知乎/抖音/小红书/ins/fb） | 需要登录态：先探一次（`/api/fetch`），读不到就按 hint 要 cookie 或要正文 |
| 链接（B站） | 字幕优先（含 AI 字幕）；无字幕抽音频 → 本地转写（FunASR paraformer-zh 优先，退回 faster-whisper），保留可点击时间戳 |
| 本地文件 | md/txt/html 直读；pdf 走 pymupdf；docx 走 zipfile；图片存 assets；音视频转写 |
| 直接粘贴的正文 | 跳过抓取，直接进第 2 步 |

**图文还是视频由工具自己判**：`note_kind=image` 走图片识字，`note_kind=video` 走「下载 → 转写 + 抽帧识字」。
判错的表现是「视频只识了封面图」或「图文被硬塞进转写」，两种都要回来修 `fetchers.py`，不要手改原料绕过。

## 2. 提炼模板（AI 必须按此结构输出）

```
## 核心观点
3-5 条，每条一句话，是这篇内容真正的主张。不复述背景，不写「本文介绍了」。

## 可执行清单
能照做的步骤 / 清单 / 参数；纯观点类内容写支撑论据。没有就写「无」。

## 概念候选
**最多 3 个**，每行四段都要有，缺一段就别提这条：
`- 概念名 —— 主张一句话｜为什么成立：本文里能支撑它的依据｜边界：什么条件下不成立｜用在哪：什么场景会用到它`

**什么才算一条有效记录**（这是本库的判定口径，AI 和用户用的是同一把尺）：

| 判据 | 过关 | 不过关 |
|---|---|---|
| 离开这条内容还成立 | 换个平台、换个人、把原文删掉，这句话照样是对的 | 「这条视频讲了 hypit」——删了原文就没了 |
| 是一个能被同意或被反对的说法 | 「量产变体不等于流量」 | 「100 个变体」「五组件骨架」（名词，不是主张） |
| 讲得出依据 | 依据能在原文里指认：具体数字 / 例子 / 原句 / 步骤 | 只有断言，或者依据是「大家都这样」 |
| 讲得出边界 | 说得出它在什么场景失效 | 放到哪都对 —— 那是废话，不是知识 |
| 用得上 | 说得出会改变你哪一个动作 | 说不出（这栏空着就别建卡） |
| 正文够厚 | 主张 + 依据 + 边界 + 用在哪，去空白 ≥ 90 字（`lint.py` 第 4 项） | 一两句话的口号 |

**一律不许当概念**（它们记录的是「这一条」，不是知识，留在原文里就够）：
产品名 / 项目名 / 仓库名 / 人名 / 账号名；许可证、版本号、运行环境、安装命令；
点赞、收藏、评论、转发、播放量、star 数、藏赞比这类互动数据；作者 IP 归属、发布时间；
被当成卖点写出来的数字口号（「1 亿播放量」那种）。

**先查库里已有的卡**：这篇如果是在印证一张已有的页，不要另起近义名，写成
`- 并入：<已有卡名> —— 主张｜为什么成立｜边界｜用在哪`，系统会把这篇追加到那张卡上。
一个主张只留一张卡；重复起名字等于把这个库搞脏（Karpathy：一条素材应该回填 10-15 张已有页，
而不是每条素材都发一张新卡）。

## 连接候选
**最多 2 条，宁缺毋滥。** 另一头必须是文末清单里已有的卡名；接不上就写「无」。
`- 本篇的主张 ↔ 已有卡名 —— 关系（前置 / 矛盾 / 同结论不同路径 / 上下位）｜为什么真的相关`

## 我的疑问
**3 条**，覆盖 边界 / 证据 / 与我 / 待验证 四类中至少两类，这是本库最值钱的产出。
每条是一个能在 20 字内问完的短问题（它直接当卡片标题），后面可跟一句为什么值得问。

## 值得记住的原话
1-3 句，用 `>` 引用格式。只挑信息密度高的句子，不为凑数而摘。

## 下一步
1-3 条具体动作（要查什么、要试什么、要丢哪些新链接进来）。
```

## 3. 入库动作

1. 原料写 `raw/clips/YYYYMMDD-标题.md`，顺序固定为
   **frontmatter → `# 原文（抓取所得，未加工）` → `# 消化稿` → `## 这张原料长成的卡`**；
   frontmatter 带 `title / aliases / source / platform / author / captured_at / method /
   images / ocr_images / frames / level / status`。
2. 概念候选：库里已有同义概念 → **追加**到那张卡并标注来源；确实没有 → 新建 `wiki/concepts/`。
   同名/近义判定走 `match_concept()`（归一化后 ≥8 字且重叠 ≥60%），认错会把两回事写进同一张页，所以宁可新建也别硬并。
3. 连接候选：关系值得独立成页 → `wiki/connections/`；另一头对不上已有卡的直接拦下不建（进 `dropped`）。
4. 疑问 → `wiki/questions/`（一张卡一个问题），同时自动排进 `inbox/tasks.md` 复习队列。
5. 卡名要能在 Obsidian 里点开：文件名和 `aliases` 才是链接目标，`title` 属性不算（`[[卡名]]` 认不出
   只有 `title:` 没有 `aliases:` 的卡）。
6. 同步 `index.md`、`log.md`、`progress.md`，并按分级排复习任务。

## 4. 分级（读到哪就停）

| 级 | 标准 | 时间 | 复习 |
|---|---|---|---|
| L0 | 知道它存在 | 5-15min | +3 天快速回顾 |
| L1 | 能定位：解决什么问题、与我何关 | 30-60min | +3 天快速回顾（**大多数内容到此**） |
| L2 | 能使用：讲出主张、证据、局限 | 2-4h | +1 天精读批注、+7 天自测 |
| L3 | 能复述、能扩展 | 半天+ | +1/+3/+14 |

## 5. 批注归位（本人写，AI 归位）

本人在任意卡片上写的「## 我的批注」会同时汇入 `inbox/annotations.md`。AI 的处理动作：

1. 读批注 → 判断它是**理解**、**质疑**、还是**新线索**；
2. 理解 → 补进对应概念卡的正文；质疑 → 变成 `wiki/questions/` 的一张卡；
3. 新线索 → 登记为「下一步」并提示要丢什么链接进来；
4. 批注原文保留在卡片里（那是他自己的话，不许改写、不许删）。
